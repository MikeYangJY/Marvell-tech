## 怎样使用

1. 打开“演示测算”。先看顶部结果，再修改浅黄底蓝字输入。
2. 先改年度同构架构单元数或净ASP，观察收入变化。再根据访谈结果调整merchant比例、技术覆盖和可争取比例。
3. 改拓扑前，确认默认模型的限制：每个端点在每个平面有一条完整链路；每Leaf与每Spine各连一条；下联上联同速率；没有第三层。
4. 缺失输入或超出端口／容量约束时，相关结果显示`#N/A`，需要补参数或改建模架构。不能用零替代缺失ASP。
5. “市场锚点”保存已核实的公司与行业数字及来源。它与演示假设分开，避免把整机收入直接代入ASIC市场。

## 默认结果怎样复算

| 输出 | 默认值 | 逻辑 |
|---|---:|---|
| 每架构单元端点 | 2,048 | 演示 |
| Leaf／Spine | 64／32 | 每Leaf 32下联、32上联，交换设备64口 |

所有商业比例、ASP和年度数量均未经一手验证。正式研究应把百分比筛选尽可能替换为“客户×架构×代际×BOM”的记录计算。

## 三个手动敏感性练习

每次只改一个变量，记录结果后恢复默认值。这些是对同一演示分组的算术练习，不是全球市场的低中高预测。

| 修改 | merchant TAM应为 | 解释 |
|---|---:|---|
| 年度单元100改为200 | 5,376万美元 | 同构部署数量翻倍 |
| ASIC ASP 4,000改为3,000美元 | 2,016万美元 | 数量不变、价格下降25% |
| merchant比例70%改为50% | 1,920万美元 | 内部自用部分扩大，外部芯片销售减少 |

更高容量ASIC可能减少芯片数量和层级，需要同时改BOM，不能只提高价格。若把2048端点直接改为4096，而其他参数不变，模型会因Spine端口不足拒绝计算。这是在提醒你重新设计拓扑。

## 已完成的验证

已检查默认算例、年度数量翻倍、零端点、零可争取份额、缺失ASP、超出两层拓扑容量等情况，并检查导出的公式和工作表布局。计算使用制表工具的重算引擎，未声称已在桌面Excel完成重新计算测试。

模型未包含库存跨年、不同ASIC ASP混合、三层fabric、breakout、CPO、软件/服务收入或客户真实订单。这些扩展需要在正式范围确认后加入，相关公式和数据字段见[市场方法](../docs/06_market_sizing.md)与[数据请求](../research/data_request.md)。
