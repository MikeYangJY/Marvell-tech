## 先决定最终要交付的市场

建议第一阶段主范围为：**全球数据中心以太网交换ASIC年度供应商收入与颗数，区分前端与AI后端scale-out，按代际、客户类型、部署地域拆分。** 建议基年为2025自然年，2026为在年估计，预测2027—2030。地域和时间均为建议，待客户确认。

Scale-up、PCIe/CXL、光DSP、AEC/retimer和DCI设为独立选项。这样客户增加产品时，可以增加模块，不用重写整个市场定义。

| 层级 | 明确定义 | 输出 |
|---|---|---|
| 整机需求池 | 指定范围内交换设备收入 | 品牌／ODM口径的外部参照，不能与芯片收入相加 |
| 全部交换硅需求 | 包括外购与内部自研使用的芯片 | 颗数／容量可汇总；内部芯片无外部售价，价值应标“等效估值” |
| Merchant TAM | 对外销售的指定交换ASIC | 外部供应商净收入、颗数，不含内部转移价值 |
| Marvell SAM | TAM中Marvell在协议、性能、软件、地域与时间上可服务的部分 | 可服务颗数×对应产品ASP |
| 可争取收入 | SAM中客户采购开放程度、项目定点、份额及爬坡支持的部分 | 按客户／项目的收入区间；不是目标份额拍脑袋乘总市场 |

**统一计价层：** 芯片按供应商净销售收入；整机按相应设备厂净收入。美元名义价格；运费、税、软件、服务、光模块是否包含逐项声明。若客户要求出货地，再保留与部署地的映射。

## 方法A 从计算设备和网络架构往上加

这是建议主模型。单位记录用“自然年×部署地区×客户类型×工作负载×物理fabric×架构×速度/ASIC代际”。

### 第一步 建年度需要配置网络的设备量

新增计算部署、替换旧设备和网络单独升级是三类事件。若使用的是年度服务器出货，已经包含替换出货，不要再叠加“存量÷寿命”。若起点是净新增装机，则另估替换，并扣掉被沿用的网络。

GPU／XPU颗数不能直接当NIC数。先查每服务器GPU数、每GPU或每服务器NIC端口数、每端口速率、多平面分配和前后端是否共用物理端口。ASIC计算平台和单机推理可能与NVL72配置相差很大。

### 第二步 逐张物理fabric数端口

用简化两层leaf–spine表示：

```text
每平面服务器连接 E = 纳入该架构的设备数 × 每设备该平面连接数
Leaf数 L = 向上取整(E / 每Leaf下联端口d)
Leaf上联链路数 F = L × 每Leaf上联端口u
Spine数至少满足 = 向上取整(F / 每Spine可用端口p)
交换机侧已用端口 = E + 2F
物理链路 = E + F
```

最后一个Spine数只是容量下限，**还需验证连接图是否能布线**。若每个leaf必须连所有spine，要同时满足端口数、每对设备链路数、上行带宽、路径数量和容错条件。超大规模集群可能要三层或多平面，不允许无限放大两层算例。

平面系数要从实际连接数推导。若一个800G逻辑带宽被拆成两个400G平面，不能把800G带宽再乘二。前端/后端物理共网则只计一次硬件，再做成本分摊。

### 第三步 从设备映射到芯片

```text
某SKU ASIC需求 = Σ(按具体架构计算的设备数量 × 每设备该SKU颗数)
年度芯片发货 = 本年交付网络所需芯片 + 提前备货/库存净变化及交付跨期调整
年度merchant收入 = Σ(对外销售ASIC颗数 × 分代净ASP)
```

给每个网络设备一个BOM映射。盒式与机箱分开，线卡ASIC和fabric ASIC分开。按企业自研、系统内部芯片和外购商用芯片分组，不能把NVIDIA整机销售额折成“Marvell可服务芯片收入”。

对历史实际最好采用供应商出货和收入口径；计算设备部署模型作需求校验。预测中显式记录芯片发货领先设备交付的时间，避免将运营商设备上线日期直接当成Marvell确认收入日期。

## 一个完整但纯演示的算例

假定一个架构单元有2,048个端点，每端点1条800G连接，一个平面；每Leaf有32下联和32上联，Spine有64端口。各Leaf分别接32台Spine，每对一条链路。

| 步骤 | 算式 | 结果 |
|---|---|---:|
| Leaf | 2,048÷32 | 64台 |
| Spine | 64×32÷64 | 32台 |
| 交换机 | 64+32 | 96台 |
| 主交换ASIC，假定每台1颗 | 96×1 | 96颗 |
| 交换侧已用端口 | 2,048+2×2,048 | 6,144个 |
| 物理链路 | 2,048+2,048 | 4,096条 |
| 全部为双端可插拔光的模块数 | 4,096×2 | 8,192只 |
| ASIC收入，假定4,000美元/颗 | 96×4,000 | 384,000美元 |

这里端口两端的定义已固定：服务器到Leaf只有一端属于交换机，但光模块仍有两端；Leaf到Spine两端都属于交换机。Breakout、AOC、双口模块和CPO会改变器件BOM，须单列。

**4,000美元ASP、端点数和每台一颗都只是演示，非Marvell报价或市场调查结果。** 与此配套的Excel还展示如何乘上架构单元数量、merchant比例、SAM比例及可争取份额。

## 方法B 从整机和端口出货校验

获取IDC或Dell’Oro的年度分速度端口出货、整机台数、收入和市场定义。若只有收入，先不要套一个统一BOM比例。

```text
ASIC收入校验 = Σ(某类设备出货 × 已确认BOM中ASIC颗数 × 该代ASIC净ASP)
```

若仅有端口量，则用对应整机实际可销售端口数映射设备，再用BOM映射芯片；同时校验breakout和端口速度统计法。整机价格中的软件、服务、光模块、电源和渠道增值不会全部进入芯片市场。

公开锚点：IDC给出的2025年325亿美元是整机范围；2026 Q2的123亿美元是单季、不能直接称全年492亿美元实际。[年度][S17] [季度][S18] Dell’Oro的2030年AI后端超过1,000亿美元预测覆盖scale-up/out/across，不能同这些历史以太网整机数字相加，也不能直接称交换ASIC TAM。[预测范围][S20]

## 方法C 用电力和机柜做可实现性校验

```text
可用IT功率预算 ≈ 已可供使用的设施MW / 对应设计PUE
AI计算功率预算 = IT功率预算 × 该类AI部署分配比例
可支持端点数 ≈ AI计算功率预算×1,000 / 每端点对应的全IT设计kW
```

若每端点功率只含GPU，先单独扣除／分配CPU、网络、存储等功率。检查本年投运而非远期规划容量；棕地改造与旧设备退出也会释放容量。该法约束部署规模，不能替代网络拓扑测算。

## 扩展到其他Marvell产品

| 模块 | 数量逻辑 | 主要需要访谈补齐 |
|---|---|---|
| 光DSP | 分距离/速率的光链路×每链路模块或光引擎数×DSP附着率×每单元DSP数 | LPO/LRO/CPO替代、双端BOM、实际价格 |
| AEC DSP | AEC线缆数×每根线缆DSP颗数 | 不能默认每端都只有一颗；和整缆价值分开 |
| PCIe交换 | 服务器／计算域数量×协议与代际采用率×每域BOM | lane分配、主机兼容、ASIC集成替代 |
| CXL交换 | 内存池数量×每池交换BOM | CPU/CXL软件支持、容量利用率和部署认证 |
| DCI coherent DSP | 数据中心对／链路×波长或通道×两端设备BOM | 距离、保护路径、波分及可插拔架构 |
| Custom ASIC | 具体客户项目出货×每系统芯片量×净价，另列NRE口径 | 定点、量产年、项目流失和供应商收入确认 |

可在同一“半导体供应商收入”层相加互不重叠器件；不要再叠加已含这些器件的整机或模块收入。CPO一体封装的对外售价只能算一次，内部拆分用于分析且须与包价勾稽。

## 建模与访谈的结合

公开资料优先确定架构和可观测规模，访谈优先验证ASP、BOM、客户采用率、认证和库存时间差。ASP至少分速度/代际、量级、芯片或整机、成交或目录价、年份；敏感价格可先问区间和相对倍数。

每个关键输入保存来源、适用范围、时间、原话摘要、区间和可信原因。两名来自同一供货链的专家可能引用同一客户订单，不算两份独立证据。历史模型与外部统计有差异时，先做口径桥接，再修正，不用“其他”硬填到吻合。

## 情景、敏感性与验收

- 基准：逐客户架构采用、分代升级和投运计划的中性路径。
- 加速：已说明哪些客户提前认证，哪些端口更快升级，以及电力是否支持。
- 延迟：量产/并网延期或既有网络复用，收入跨期而非必然永久消失。
- 单变量敏感性优先看部署量、以太网采用量份额、每端点端口、拓扑层级、ASIC ASP和merchant可进入比例。份额与ASP可能相关，不应同时不加解释地设到最高。

建议验收标准：所有汇总可追到BOM及输入；覆盖主要客户和代际；供需两种方法差异形成可解释桥接；高影响参数有至少两类独立证据或明确的未解决区间；分别给出实际、估计、预测和已知盲区。
